# Пепел Княжеств

Мрачная онлайн-игра в формате текстовой RPG-рогалика. Мир вдохновлён славянским фэнтези и суровой моральной неоднозначностью, но строится как самостоятельная вселенная.

## Вертикальный срез 0.14

Проект содержит две серверные сюжетные главы, две области свободных походов, личные и гильдейские боссы, ремесленную экономику и постоянные гильдии:

- один адаптивный PWA-интерфейс для компьютера и телефона;
- регистрация, HttpOnly-сессии, SQLite-база и серверный герой одного из шести ремёсел;
- первая глава в Верескове и вторая глава в Соляных топях;
- окончательная смерть, поколения наследников, слава рода и наследуемые торговые активы;
- свободные области **Пепельный тракт** и **Соляные топи** с суточными авторскими контрактами;
- одиночные и групповые столкновения, выбор цели, дистанция, высота и зоны контроля;
- независимые слоты **основная рука**, **броня** и **оберег**;
- личный региональный босс **Соляной воевода Глухобор**;
- серверные гильдии до 20 участников, пользовательские роли, дерево развития и еженедельные задания;
- отдельные монетная и ресурсная казны;
- добровольная и автоматическая передача власти главы;
- совместная подготовка и асинхронный гильдейский рейд против **Пепельного князеглода Чернопола**;
- серверное резервирование и атомарное потребление материалов подготовки;
- идемпотентные взносы, выдачи, записи в дружину, рейдовые действия и награды;
- приватные API отвечают с `Cache-Control: no-store` и не попадают в Service Worker;
- схема 0.14 устанавливается миграцией `017_guild_resources_leadership_and_raids`.

## Ресурсная казна

Гильдия хранит реальные материалы, а не только общий числовой показатель. Каждый складской предмет содержит:

- название и идентификатор;
- общее количество;
- зарезервированную часть;
- доступный для выдачи остаток;
- время последнего изменения.

Любой участник может внести разрешённый материал из личного серверного инвентаря. Выдавать незарезервированные материалы могут только роли с правом распоряжаться казной. Повтор одного `requestId` не списывает предмет второй раз.

В журнале отдельно отмечаются взнос, выдача, резервирование, снятие резерва, потребление подготовкой и рейдовая награда.

## Преемственность главы

Действующий глава может добровольно передать власть любому участнику. Новый глава получает защищённую роль с позицией 100 и полными правами, прежний глава становится заместителем с позицией 80.

Автоматическая передача происходит, когда:

1. глава не проявлял серверной активности более 14 дней;
2. в гильдии есть другой участник, активный за последние 7 дней;
3. преемник выбирается по наивысшей роли, затем по свежести активности и времени вступления.

Все смены власти записываются в неизменяемый журнал. Для существующих гильдий миграция начинает новый четырнадцатидневный период, поэтому старые даты вступления не вызывают мгновенное смещение главы.

## Первый гильдейский босс

**Пепельный князеглод Чернопол** является общим серверным противником одной гильдии. Его состояние одинаково для всех участников:

- чешуйчатый венец выполняет роль щита;
- после разрушения венца урон проходит в здоровье;
- ответные действия уменьшают общий боевой дух дружины;
- победа наступает при нулевом здоровье босса;
- поражение наступает при нулевом духе или полном исчерпании личных действий.

Перед записью дружины гильдия должна зарезервировать:

- 12 единиц лома железа;
- 10 единиц чёрного тростника;
- 6 единиц утопленной бронзы;
- 8 единиц соляного мха;
- 4 рассольных кристалла;
- 1 Сердце белого колокола.

До начала боя подготовку можно отменить. Резерв снимается, а всем записавшимся героям возвращаются потраченные 3 силы.

Для вступления нужен живой герой не ниже 4-го уровня без активного личного похода. В обычной гильдии требуется не менее двух действующих участников; одиночная гильдия может начать испытание одним героем. Каждый участник получает не более 12 действий.

Доступны:

- **Штурм** — наибольший прямой урон;
- **Держать строй** — поддержка боевого духа;
- **Приём ремесла** — уникальное соотношение урона, поддержки и снижения ответного давления для каждой профессии.

Личную награду получают только участники, совершившие хотя бы одно действие. Победа выдаёт каждому такому герою 35 монет, 6 репутации и Чёрную чешую князеглода. Гильдия получает 120 монет, 140 опыта, три Осколка пепельного венца и одно дополнительное очко дерева за первую победу. Повторный вызов открывается через семь дней; после поражения новая подготовка доступна через сутки.

## Экипировка и групповой бой

У героя три независимых слота:

1. **Основная рука** — оружие или ремесленный инструмент.
2. **Броня** — уменьшает физический урон.
3. **Оберег** — даёт сопротивление порче, контролю, движению или работе с высотой.

Групповой контракт означает одного героя против нескольких серверных противников. Каждый враг имеет отдельное здоровье, роль, намерение, дистанцию, высоту и силу зоны контроля. Игрок выбирает цель для атаки, ремесленного приёма и ловушки.

## Авторская процедурность

Свободный контракт не генерируется из произвольных слов. Сервер соединяет совместимые заранее написанные модули области, противника, цели, местности, осложнения, награды и трофея. Одинаковая суточная ротация для конкретного аккаунта восстанавливается с теми же идентификаторами.

## Текущее техническое ограничение

Гильдейский рейд общий, но асинхронный: клиент обновляет его состояние серверными запросами и опросом, а не отдельным боевым WebSocket-каналом. Участники не обязаны находиться онлайн одновременно. Рейд пока не меняет общую карту мира, не содержит нескольких фаз и не допускает подключение после начала боя.

## Запуск

Требуется Node.js 22.13 или новее.

```bash
npm install
npm run dev
```

PWA откроется на `http://localhost:5173`, API и сервер чатов работают на `http://localhost:3001`.

Команда `npm run dev` запускает сервер и Vite напрямую через Node.js и работает в Windows, Linux и GitHub Codespaces.

Раздельный запуск:

```bash
npm run dev:server
npm run dev:web
```

Данные сохраняются в `data/game.db`, история чатов — в `data/chat.json`. Эти файлы не попадают в Git.

## Production

```bash
npm run build
npm start
```

После сборки Node-сервер отдаёт PWA, REST API и WebSocket на одном порту. По умолчанию используется порт `3000`; `PORT` и `DATABASE_PATH` можно переопределить переменными окружения.

## Команды

```bash
npm run dev          # клиент и основной сервер разработки
npm test             # серверные тесты и дымовой тест игрового движка
npm run check        # строгая проверка TypeScript
npm run build        # тесты, типы и production-сборка
npm start            # production-сервер
```

## Принципы проекта

1. Ремесло открывает способы решения проблем, а не только проценты к характеристикам.
2. Процедурность собирается из авторских модулей и не разрушает голос мира.
3. Мир не делится на очевидное добро и зло, но последствия решений понятны задним числом.
4. Рогалик наказывает за риск, сохраняя память рода, а не отменяя цену смерти.
5. Сервер является источником истины для боя, регионов, сюжета, героя, гильдий и экономики.
6. Система считается завершённой только после проверки миграции, повторов запросов, прав доступа и сетевых сбоев.
